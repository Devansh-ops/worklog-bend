# Independent domain law review

Reviewed 2026-11-08. This file distinguishes required product invariants from actual mechanically checked results. A finite fixture is a behavioral witness or counterexample, not a universal proof.

## Requirements retained

The accepted requirements remain those in SPEC and DOMAIN_CONTRACTS. In particular, merge must reject inconsistent content for an ID, preserve every distinct event, and have a unique canonical result independent of arrival order. Deletion preserves a tombstone and privacy provenance. Eligibility is a positive set of authoritative public live task IDs. Notes-off withholds every automatically note-derived field, including secondary summary/report paths. A timestamp watermark is not checkpoint coverage. Publication executes the exact approved immutable plan against its approved read revision, then acknowledges only that plan's unchanged pending events.

No proof may replace these claims with an assumption that its own result is correct. Valid-state predicates must have concrete inhabited witnesses, and collision-free preconditions must not accidentally rule out all nonempty inputs. A function's purity makes repeated evaluation deterministic, but reflexivity alone does not establish event membership, canonical ordering, merge algebra, or compatibility.

## Representation obligations

- An Event constructor with both a canonical JSON string and decoded fields permits inconsistent pairs. Comparing only the string does not establish equality of arbitrary Bend Event values. Either compare all modeled fields as well, or explicitly scope claims to a certified decoder image and test that certification boundary independently.
- Raw JSON structural equality includes retained unknown fields and array order. Duplicate object keys must be rejected before ordinary JSON parsing erases them. Bend proofs over normalized values do not establish that host behavior.
- Normalized UTC string order and ordinal event-ID order need a specified comparator and actual order lemmas for universal sorting/merge algebra. Runtime sample agreement is useful but insufficient.
- A checkpoint coverage ID set alone is insufficient for applying late events directly onto a snapshot. A late older status must be inserted before newer covered statuses. The implementation uses authoritative canonical replay, with verified source-cache coverage; it does not apply an unproved incremental tail to a state snapshot.
- A privacy proof must cover task-linked historical events and secondary context as well as current board tasks. Free text explicitly selected by the user remains separate disclosed input, with no semantic-redaction promise.
- A Git fast-forward does not prove preservation of a peer's events if file contents were prepared against a different read revision. The effect adapter must bind its parent and base tree to the approved plan and reject a mismatch.

## Actual checks

Checked against Core.bend from `fb808b6`, Publication.bend from `6824b2b`, and Reports.bend from `f0806c7`. The core update adds prospective command replay validation without changing merge/equality/replay algorithms. Bend 2.0.40 at source commit `70607d7f740e3b3f4a1edc61069df8ab88491696`, Bun 1.3.10, and Lean 4.34.0 accepted root `PROOF.bend --verdict` with `ALL PROOFS CHECK` and exit 0. The source and toolchain version/integrity checks are independent of this law review.

There are 168 root law declarations, plus supporting proofs in Equality, Membership, Count, Unique, Order, Sort, ChronologicalSort, Canonical, MergeSets, Consistent, Algebra, PlanningLaws, Replay and HistoryPrivacy. The declaration count includes supporting comparator/equality/membership/count lemmas, existential witnesses and concrete regression witnesses. It must not be described as 168 independent application guarantees.

Run the complete verification gates from this repository root after installing
the pinned tools as described in BEND_TOOLCHAIN.md:

```sh
npm --loglevel verbose run check:build
npm --loglevel verbose run test:proof
```

Both returned exit 0. The mutation harness first requires the unmodified root verdict and the standalone runtime-only mutation-witnesses.bend fixture to succeed. It then makes isolated copies under ignored tmp/proof-negative-* directories. Each mutation must fail a named finite counterexample in that runtime-only fixture, and must also fail the full root proof gate. The standalone fixture imports no proof-support modules, preventing failure of a still-true support theorem's shape-dependent proof from masquerading as an actual false-property counterexample.

All thirteen deliberate mutations were rejected: historical note deliveries with notes-off; notes with notes-off; ignored private flags; unsupported-schema gate bypass; substituted publication plans; omitted distinct events; firing disabled reminders; firing on complete days; ineligible report tasks; accepted inconsistent event content; corrupted complete event data with retained IDs; retained duplicate deliveries; and bypassed prospective replay validation for a new note before its task creation. Missing tools or infrastructure errors do not satisfy the named-counterexample assertion. Diagnostics for both checks remain in each temporary directory; production files are unchanged. The default wrapper is the repository-local scripts/bend-linux.sh; no environment override is required.

Native Windows Bun accepted single-file checks but the pinned compiler rejected ordinary multi-file Windows import paths. These domain checks therefore used the working WSL route. The compiler source was not modified to bypass that limitation.

## Accepted model scope and host boundaries

The important modeled law families above are accepted by the real pinned verdict kernel: canonical merge membership, full content, multiplicity/ID uniqueness, order, conflict rejection, consistent success and algebra; typed completion/deletion and accepted-command replay closure; source-coverage authoritative recovery and latest folded records; current/historical privacy and note policy; schema/plan preservation; exact publication approval and pending acknowledgement; report exclusion and pure reminder guards. This is verification of the stated pure-domain invariants, not universal verification of every feature or every possible domain relation.

The recovery implementation deliberately uses verified source caches and authoritative full replay. It makes no incremental-tail-on-snapshot correctness claim. Canonical ordering plus universal note status/completion preservation supports the recovery argument; the detailed eight-event whole-state and backdated-note results are nonempty witnesses, not a universal theorem that every malformed history is complete. Unsupported/incomplete histories remain diagnosed and fail closed.

Provider request bytes, stale proposals, endpoint classification, explicitly disclosed free text, retries, browser effects, multi-tab journals, Git ref races, read-base binding, JSON duplicate-key validation, unknown-field retention, generated JavaScript, calendar conversion, report formatting and OS scheduling require adapter/integration/browser checks. STATUS.md records executed checks for these boundaries separately. No proof here certifies arbitrary provider responses or live network effects. The failed-publication theorem concerns the acknowledgement function's failure input; host outcome classification, including ambiguous failures, remains an effect-boundary responsibility.

No law uses unsafe axioms or foreign effects. Proof guarantees remain scoped to the modeled values accepted by the pinned checker and verdict kernel; the compiler translation and host boundaries are not proved by these results.

The final 168-declaration root gate includes PlanningLaws, Replay, Consistent, Algebra and HistoryPrivacy dependencies and returned ALL PROOFS CHECK, exit 0. The expanded thirteen-mutant harness also returned exit 0 after rejecting every named false-property witness and full root mutation. The timestamp-watermark incremental-tail design is retired in favor of verified source-cache coverage and authoritative full canonical replay.
